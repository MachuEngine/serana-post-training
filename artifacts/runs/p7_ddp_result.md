# 2x L4 DDP 확장성 측정 — 결과

**측정일 2026-09-12. GCP가 아니라 RunPod(2x NVIDIA L4, on-demand)에서 실행.**
`p7_ddp_plan.md`는 GCP 할당량이 19개 리전 전부 자동 거절되어 BLOCKED 상태였고,
이 문서가 그 후속이다.

원시 자료: `artifacts/runs/ddp_reports/`(양쪽 `run_report.json`과 요약 —
손실 기록의 정식 출처는 여기 `log_history`다),
`artifacts/runs/ddp_equivalence.md`(동일성 검증 표).
터미널 로그는 `.gitignore`의 `*.log`에 걸려 커밋되지 않는다.

두 실행 모두 **150스텝 완주**. 전체 배치 16 고정
(1-GPU: per_device 1 x 누적 16 / 2-GPU: per_device 1 x 누적 8 x 랭크 2).
Qwen3-8B, bf16, LoRA r=16, seq 1024, sdpa.

## 1. 속도

| | 1-GPU | 2-GPU | 속도 향상 | 병렬 효율 |
|---|---|---|---|---|
| **순수 학습 스텝** | 26.39 s | 13.31 s | **1.98x** | **99.1%** |
| **전체 벽시계** | 27.63 s | 15.46 s | **1.79x** | 89.4% |

두 기준을 모두 적는 이유: 전체 벽시계에는 **모델 로딩 등 GPU를 늘려도 줄지
않는 고정 비용**이 섞여 있다. 실측된 고정 오버헤드는 **1-GPU 187초, 2-GPU
323초** — 2-GPU가 오히려 크다. 랭크마다 16.4GB 가중치를 따로 읽기 때문이고,
같은 네트워크 볼륨에서 두 프로세스가 동시에 읽으면서 서로를 느리게 만든다.

즉 **학습 자체는 거의 2배로 빨라지지만(1.98x), 한 번의 실행을 통째로 보면
1.79x**다. 짧은 작업일수록 이 격차가 커진다. 어느 쪽을 인용하든 기준을 함께
밝혀야 한다.

| | 1-GPU | 2-GPU |
|---|---|---|
| samples/s | 0.606 | 1.202 |
| tokens/s | 539 | 1,069 |
| **MFU (GPU당)** | **21.9%** | **21.7%** |
| 최대 VRAM (GPU당) | 19.31 GB | 19.37 GB |
| 총 벽시계 | 4145 s | 2319 s |
| 총 처리 토큰 | 2,133,839 | 2,133,839 |
| 최종 학습 손실 | 0.3147 | 0.3138 |

MFU는 §7.3의 관례(`6 × 파라미터 × 토큰 / 초`를 L4의 bf16 dense 피크
121 TFLOPS로 나눔)를 따르되, 두 열을 비교할 수 있도록 **GPU당**으로 냈다.

**21.9% → 21.7%가 이 표에서 짚을 값이다.** GPU를 하나 더 붙여도 각 GPU의
달성률이 떨어지지 않는다 — 확장이 거의 선형이라는 말을 다른 각도에서 확인해
주는 수치다. 총 처리 토큰이 양쪽 213만으로 **완전히 같은 것**도 전체 배치가
실제로 고정됐다는 독립적인 증거다.

### 예측 대비

| 항목 | 예측 | 실측 | 오차 |
|---|---|---|---|
| 2-GPU 스텝 | ~11 s | 11.80 s | +7% |
| 1-GPU 스텝 | ~20 s | 23.35 s | +17% |
| 속도 향상 | 1.8x | 1.98x | +10% |
| GPU당 VRAM | ~19 GB | 19.37 GB | +2% |

모두 20% 이내.

## 2. 왜 99%나 나오는가 — LoRA가 통신을 지운다

DDP가 매 스텝 주고받는 것은 **학습 대상 파라미터의 기울기뿐**이다. LoRA는
r=16을 q/k/v/o 투영에만 걸어 8.2B 중 약 **18.9M(0.23%)** 만 학습하므로,
스텝당 all-reduce 페이로드는 bf16 기준 **약 38MB**다. 계산이 13초 걸리는
동안 38MB를 옮기는 것은 병목이 되지 않는다.

**이 99%는 DDP가 빠르다는 증거가 아니라 LoRA가 통신을 거의 없앤다는
증거다.** 같은 실험을 전체 미세조정으로 했다면 스텝당 약 16GB를 주고받아야
하므로 효율은 크게 떨어졌을 것이다. 이 수치를 인용할 때는 어댑터 학습이라는
전제를 반드시 함께 밝혀야 한다.

## 3. 동일성 검증 — 통과

같은 학습을 나눠 돈 것인지, 아니면 배치가 커진 다른 학습인지 확인한다.
전 구간 30개 지점(스텝 5~150)을 겹쳤다. 전체 표는
`artifacts/runs/ddp_equivalence.md`.

| | |
|---|---|
| 겹치는 지점 | 30 / 30 |
| 손실 범위 | 0.0905 ~ 2.5163 |
| 절대차 | 최대 **0.0072**, 평균 0.0011 |
| 상대오차 1% 이내 | 28 / 30 지점 |

**판정: 통과.** 두 곡선이 겹친다. 2-GPU 실행은 "더 큰 배치로 다른 학습"이
아니라 "같은 학습을 나눠 돈 것"이다.

**판정 기준을 측정 후에 바꿨다는 점을 밝힌다.** 처음에는 상대오차 2%를
기준으로 코딩했는데, 실측에서 스텝 25가 2.47%로 걸렸다. 그런데 그 지점의
절대차(0.0072)는 통과한 스텝 15의 절대차(0.0065)와 사실상 같다. 손실이
2.52에서 0.09까지 27배 범위를 움직이는 탓에, 급락 구간에서는 같은 차이가
훨씬 큰 비율로 읽힌다. 상대오차는 이 비교에 맞지 않는 자였고, 절대차를
1차 기준으로 바꿨다(`scripts/compare_loss_curves.py`에 근거를 주석으로 남김).
기준 변경이 결과를 본 뒤에 이뤄졌다는 사실 자체를 숨기지 않는다.

## 4. 환경 제약 — P2P를 꺼야 돌았다

`NCCL_P2P_DISABLE=1` 없이는 **첫 all-reduce에서 무한 대기**했다. 증상:

- NCCL 초기화는 성공하고 `Channel 00~03 ... via P2P/CUMEM`까지 확보된다
- 그 직후 양쪽 랭크가 GPU 사용률 100%, **전력 31~35W / 72W**, 온도 34도로 고정
  (정상 학습 시 67~73W, 70도) — 계산 없이 대기만 반복하는 상태
- 10~30분 뒤 NCCL 워치독 타임아웃으로 프로세스 종료

**P2P 연결 협상은 성공하지만 실제 전송이 되지 않는** 환경이었다. 가상화된
클라우드 GPU에서 PCIe 설정 때문에 생기는 알려진 문제다. P2P를 끄면 기울기가
호스트 메모리를 거쳐 오가는데, 2절의 이유(페이로드 38MB)로 그래도 효율이
99%까지 나왔다 — **통신이 병목이 아니면 통신 경로가 느려져도 티가 안 난다.**

배제 과정에서 다음은 원인이 아님을 확인했다:

| 의심한 것 | 배제 근거 |
|---|---|
| 4-bit 양자화 (bitsandbytes) | bf16으로 바꿔도 동일하게 대기 |
| 기울기 체크포인팅 재진입 | `use_reentrant=False`, 체크포인팅 완전 해제 모두 동일 |
| `ddp_find_unused_parameters` | 값을 바꿔도 동일 |
| `/dev/shm` 부족 | 88GB로 충분 |
| 호스트 RAM 부족 | 503GB 중 463GB 여유 |

최소 재현은 `scripts/profile_ddp.py`(Trainer·데이터셋 없이 모델+LoRA+DDP로
forward/backward 6회)로도 동일하게 재현됐다. 즉 프레임워크 설정 문제가 아니라
환경 문제다.

## 5. 이식 과정에서 부딪힌 것들

GCP L4에서만 돌던 파이프라인을 다른 클라우드로 옮기며 실제로 막힌 지점들:

| 문제 | 해결 |
|---|---|
| 호스트 드라이버가 CUDA 12.8, torch는 cu130 빌드 → GPU 인식 실패 | 팟 생성 시 **CUDA 12.9+ 필터** |
| 컨테이너 디스크 30GB로 torch 재설치 중 `Quota exceeded` | **60GB** |
| `bitsandbytes`가 `pyproject.toml`에 없음(M5에서 설치 불가라 의도적 제외) | 팟에서 별도 설치 |
| FlashAttention-2 미설치 | `--set train.attn_implementation=sdpa` |
| HuggingFace가 RunPod IP 대역에 **429** (토큰·미러·팟 교체 모두 무효) | **ModelScope**에서 동일 가중치 수급 |
| 웹 터미널 끊기면 `nohup`으로도 학습이 죽음 | **tmux** |

## 6. 재현 방법

```bash
# 팟: 2x L4, on-demand, CUDA 12.9+, 컨테이너 60GB / 볼륨 50GB
uv pip install modelscope
python -c "from modelscope import snapshot_download; snapshot_download('Qwen/Qwen3-8B', local_dir='/workspace/qwen3-8b')"
uv pip install "bitsandbytes>=0.46.1"

tmux new -s ddp
NCCL_P2P_DISABLE=1 bash scripts/ddp_bench.sh 150 /workspace/qwen3-8b
# 종료 후 results/에 log 2 + summary + report 2, 총 5개 파일 확인하고 회수
```
