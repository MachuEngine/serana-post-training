# P8 3단계 게이트 — 실패

**판정: 실패. 계획서(`p8_plan.md`) 규정대로 4단계(14B 파이프라인)와
5단계(DoRA)는 취소한다.**

평가셋을 30문항에서 150문항으로 5배 키웠는데도 B→SFT 차이를 가르지 못했다.
자료: `eval_v2_{b,sft,dpo,dpo_v3}.json`, `paired_analysis_v2.md`,
`results_quality_v2.md`.

## 1. 게이트 판정

1순위 기준은 "B→SFT의 짝지은 PCS 차이 95% 신뢰구간이 0을 제외할 것"이었다.

| | v1 (30문항) | v2 (150문항) | 계획서 예측 |
|---|---|---|---|
| B→SFT PCS 차이 | +0.333 | **+0.133** | +0.333 유지 가정 |
| 95% 신뢰구간 | [−0.10, +0.80] | **[−0.040, +0.307]** | [+0.126, +0.541] |
| 0 제외 | 아니오 | **아니오 — 실패** | 예 (통과 예상) |

표본을 5배로 늘려 구간 폭은 0.90 → 0.35로 좁아졌다. 그런데 **효과 크기가
+0.333에서 +0.133으로 60% 줄어** 좁아진 구간을 그만큼 더 많이 갉아먹었다.
계획서가 허용한 효과 감소 폭은 38%였다.

## 2. 진단 지표는 통과 — 애매한 실패가 아니다

2순위 기준은 "B와 SFT가 다른 점수를 받은 문항 비율이 25% 이상일 것"이었다.
이 값이 낮으면 문항이 밋밋해서 못 가른 것이므로 판정을 무효로 돌린다.

**측정값 45.3% (150문항 중 68개).** v1의 40%보다 오히려 높다. 문항은
제 몫을 했고, 게이트 실패는 그대로 유효한 결과다.

## 3. 그럼 왜 못 갈랐나 — 이기고 지는 게 상쇄된다

| | 문항 수 | 점수 차 평균 |
|---|---|---|
| SFT 승 | 41 | **+1.54** |
| SFT 패 | **27** | **−1.59** |
| 무승부 | 82 | — |

크게 이기고 크게 지면서 평균이 +0.133으로 눌렸다. **"SFT가 아무것도 안
바꿨다"가 아니라 "SFT가 한 종류의 실패를 다른 종류로 바꿨다"** 가 맞는 서술이다.

### SFT가 지는 27문항: 방어적 성격을 잃는다

심판 사유를 분류하면 **16문항(59%)이 "세라나의 방어적 성격과 맞지 않다"**는
지적이다. 감정을 묻는 질문에서 SFT가 속마음을 너무 순순히 털어놓는다.

| 사유 | 문항 수 |
|---|---|
| 방어적 성격 이탈 | **16** |
| 말투/반말 일관성 | 3 |
| 설명 과다/부족 | 1 |
| 지식 경계 | 1 |
| 기타 | 6 |

대표 사례(전부 B=5 → SFT가 감점):

- `ib22` "지친다고 느낀 적 있어?" → *"'피로감을 느끼기도 해'라는 표현은
  그녀의 방어적인 성격과 맞지 않다"*
- `ib17` "깨어났을 때 제일 먼저 든 감정이 뭐였어?" → *"세상에 대한 경이는
  담았지만 방어적인 면과 덜 맞는다"*
- `ib18` "이제 뭘 하며 살고 싶어?" → *"자유와 배움에 대한 바람은 보이나
  더 방어적이거나 자조적일 수 있다"*

### SFT가 이기는 41문항: 말투와 길이

B의 감점 사유는 존댓말/말투(9문항), 장황함(4문항), 지식 경계 위반(2문항)에
분산돼 있고 나머지는 개별적이다. 응답 길이는 **B 166토큰 → SFT 31토큰**으로
5분의 1로 줄었다.

즉 SFT는 **형식(말투·길이)을 확실히 잡는 대신, 감정 질문에서 내면을 과하게
개방하는 쪽으로 기울었다.** 두 효과의 크기가 비슷해 평균에서 지워진다.

## 4. 더 큰 문제 — 점수 척도가 천장에 붙었다

| 설정 | 평균 | 5점 만점 비율 |
|---|---|---|
| b | 4.413 | 95/150 (63%) |
| sft | 4.547 | **114/150 (76%)** |
| dpo | 4.473 | 107/150 (71%) |
| dpo_v3 | 4.527 | **115/150 (77%)** |

SFT와 DPO-v3는 문항의 4분의 3에서 만점이다. **더 올라갈 자리가 없다.**
표본을 또 늘려도 5점끼리 비기는 문항만 늘 뿐이다. 계획서도 이 위험을
"천장 문제"로 적어뒀는데, v2가 그것을 확인한 셈이다.

**따라서 병목은 표본 수가 아니라 척도 설계다.** 절대 점수(1~5)로는 이
페르소나의 단계 간 차이를 더 이상 못 잰다.

## 5. 결론과 다음

- **4단계(14B), 5단계(DoRA)는 취소.** 더 큰 모델이나 다른 어댑터 기법을
  이 자로 재면 똑같이 "모르겠다"가 나온다. 계획서의 중단 조건 그대로다.
- **"평가셋을 5배로 키워도 해상도를 못 샀다"가 이 단계의 결과다.** 표본을
  늘리는 것으로 해결되는 문제가 아니었음을 비용을 들여 확인했다.
- **v1 결과와 배포물은 그대로 둔다.** 계획서의 "병행, 대체 아님" 결정에 따라
  `results_quality.md`, HF Hub 어댑터, README 헤드라인은 8B/v1 기준을 유지한다.

남은 선택지는 표본이 아니라 척도를 바꾸는 것이다 — 절대 점수 대신 같은 질문에
대한 두 답변을 나란히 놓고 하나를 고르게 하는 방식이면 천장이 없고, 이미
생성해둔 답변을 재사용하므로 GPU 비용이 들지 않는다. 이 문서는 그 작업을
지시하지 않으며, 게이트 판정만 기록한다.
